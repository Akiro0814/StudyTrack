# StudyTrack 两端可靠性与界面统一

## 现状与判断

iOS 使用 SwiftUI + GRDB，已有结构化学习阶段、科目继承、跨学期分析、WidgetKit 和完整备份契约。Android 使用 Compose + Room + DataStore，页面和业务能力明显落后于 iOS。继续维护两套原生客户端，复用现有数据，避免重写或清库。iOS 的信息结构、20pt 页面边距、26pt 卡片圆角、蓝色强调色、四个标签和中文文案作为两端设计基准。Android 玻璃必须使用 Kyant Backdrop 的真实背景采样。

## 实施范围

1. 云备份：保留有正式 entitlement 的容器和自签场景的用户授权文件夹两条路径；协调读写、大小限制、占位文件、错误隔离、取消、授权恢复、恢复前 revision 检查。保存和实际云端传输分别展示。
2. 小组件：稳定且有数据的默认选择、明确失效配置、成绩隐私隔离、后台原子写入、锁屏可读、删除/恢复/切换后刷新、深链验证。App Group 授权缺失给出可行动说明。
3. 引导：完整介绍档案/阶段/科目、单条与批量录入、分数/排名/反思、列表编辑删除撤销、分科和跨科跨学期分析、Excel/完整备份、头像/主题/壁纸、小组件/隐私。分页与档案设置转场、进入首页展开动画，遵循减少动态效果。
4. 品牌：安装最终 B 版既有资源，同步 AppIcon、BrandMark、Android 启动与设置图标。
5. Android：保留 Room 历史数据；迁移结构化学期和科目谱系、全阶段和多科分析、头像、外观模式、完整备份恢复、桌面小组件、删除撤销；四标签、首页、科目、分析、设置、表单采用同一组件体系。系统文件选择器及平台权限按各自系统运行。iCloud 和 iOS 锁屏 WidgetKit 不迁移。

## 验收

先运行现有数据库契约和核心测试，再加入失败回归用例。Android 运行单测、lint、APK 构建及隔离模拟器交互；iOS 运行核心测试、模拟器 UI 测试、扩展和真机 arm64 构建。UI 用小屏/标准屏、大字体、浅深色、空数据/多用户/跨学期场景验证。所有测试数据为合成数据。

Windows 没有 Xcode；优先使用现有交付仓库的独立分支与已有 CI 获取 macOS 验证。不得把旧日志、静态检查、无签名 IPA 或本地文件 round-trip 写成真实 iCloud 上传/跨设备恢复或签名设备 WidgetKit 验证。真实云账号和设备不可用的部分必须标注未验证。
